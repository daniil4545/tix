## Новые must-fix

M-1. spec.md:133, 159. `move --after` не ставит задачу первой. Р6: приоритет - порядок;
`ctx` берёт следующую из `ready` по `rank`. Сценарий: «T-19 срочно, сделай первой» или
`K` в TUI на второй карточке. Команды нет. CONFIRMED по тексту.
Предложение: `--after T-9 | --first`; без колонки `--after` берёт колонку соседа.

M-2. spec.md:159-164, 198-199. TUI не может перенести в `waiting` и закрыть с `--force`.
Р41 требует поле `waiting`, Р40 требует `-m`. После Р44 `$EDITOR` правит только тело,
ввода полей в TUI нет. Сценарий: человек жмёт `m` на `blocked`, получает отказ и в TUI
не может его исправить. CONFIRMED по тексту.
Предложение: при переносе в `waiting` и `closed --force` TUI спрашивает одну строку.

## Should-fix

S-1. spec.md:180-182. «PID родительского процесса агента» читается двояко. Буквально
`getppid()` у `tk` - это `bash -c` на каждую команду. Тогда у каждой команды своя личность.
Повторный `take` получит отказ «чужой захват», продление `claim` сломается. Написать:
подняться по дереву процессов до процесса с именем агента и взять его PID.
`CLAUDE_CODE_SESSION_ID` нет в разделе 9 как проверенного факта: добавить или пометить.

S-2. spec.md:104. Назвать, что коммит шага 5 берёт только путь операции. Иначе правка
Obsidian в другом файле между шагами 2 и 5 уйдёт под сообщением агента.

S-3. spec.md:104. Ответ CLI при упавшем коммите не назван. Агент на `err` повторит
`comment`, будет дубль. Ответ: «записано, коммит отложен», код 0 или отдельный код.
`backup` перед push выполняет шаг 2, иначе незакоммиченная правка не уйдёт в бэкап.

S-4. spec.md:100, 162. Слияние `edit` идёт по телам трёх версий: тело из blob `rev`,
текущее, новое. Строка `## Комментарии` внутри нового тела - отказ.

S-5. spec.md:97-98. external edit для файлов без id (`Untitled.md`, `.obsidian/*`,
`RULES.md`): назвать сообщение или правило игнора.

S-6. spec.md:254. Цель 10 мс на 1000 задач спорна. Запуск бинаря с Charm уже 8,5 мс
(раздел 9). На разбор 1000 frontmatter остаётся 1,5 мс. `make bench` упадёт в первой
задаче. Поднять цель или назвать кеш индекса. Решение пользователю (Р44).
