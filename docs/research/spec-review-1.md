## Вердикт

## Must-fix

M1. spec.md:141-142, 211-212. Не сказано, какой файл открывает `$EDITOR`. Если сам файл задачи,
агент пишет комментарий, vim по `:w` его затирает. Слияния нет, правка пропадает из файла.
Swap-файл vim уходит коммитом external edit. PLAUSIBLE.
Предложение: редактор правит копию в `.tracker/tmp/` (в `.gitignore`). Ядро отвергает тело
с `<<<<<<<`. При повторном открытии база - текущая версия. Файл не изменён - отмена.

M2. spec.md:111, 137-138, 235. Заметка - пустой коммит. `git log -- <файл>` пропускает коммиты,
не менявшие путь. Заметки не попадут в историю карточки. CONFIRMED (упрощение истории git).
Предложение: история - `git log --grep '^T-12:'`. Сообщение external edit перечисляет id.
Имя файла после создания не меняется.

M3. spec.md:100, 107. Точка невозврата не названа: rename прошёл, `git commit` упал. Причины:
висящий `index.lock` после убитого процесса, глобальный `commit.gpgsign`, хуки. Висящий
`index.lock` блокирует все записи навсегда. Следующая операция коммитит правку агента как
external edit без автора. PLAUSIBLE.
Предложение: git с `-c commit.gpgsign=false -c core.hooksPath=/dev/null`. Читатели (TUI,
`git status`) с `--no-optional-locks`. `index.lock` под нашим локом считается висящим:
удалить и записать в лог. Сообщение неудачного коммита сохранить в `.tracker/pending`.
Следующая операция коммитит с ним.

M4. spec.md:176, 209, 259. Личность агента не определена, а на ней держится `claim`.
OpenCode без id сессии. Две сессии Claude неразличимы, если в `claim` только имя.
Новая сессия продолжает задачу и получает отказ на 3 часа. Не сказано, какие команды проверяют
`claim` и чья команда его продлевает. PLAUSIBLE.
Предложение: `claim` хранит имя агента и короткий id сессии. У OpenCode флаг `--as` или PPID.
`claim` проверяет только `take`. Продлевает только команда владельца. `take --steal`
по правилу из `RULES.md`. См. вопрос В-1.

M5. spec.md:36, 40, 194, 210. В CLI нет команды для полей (`ask`, `waiting`, `due`, `tags`,
`title`), абстракта, раздела «Подробно» и замены тела. Сценарий «агент заменяет тело по старой
версии» не исполнить. Агент правит файл своим Edit: автор теряется, проверка Р11 обходится.
CONFIRMED.
Предложение: `tracker set T-12 ask="..."` и `tracker edit T-12 --base <rev> < файл`.
`show` печатает `rev`.

M6. spec.md:264. Номер «под локом» без источника. Если это максимум по файлам, удалили последнюю
задачу, новая получит тот же id. Её история смешается с удалённой. PLAUSIBLE, частый случай:
агент удалил дубль идеи.
Предложение: счётчик `.tracker/next_id` под локом, в git.

M7. spec.md:245-250. «Happy path в живых сессиях» без исполнителя и pass/fail нарушает Р33.
`make check` на временной папке требует переменную корня, она не названа.
Предложение: `TRACKER_HOME`. `make e2e-agents`: `claude -p`, `codex exec`, `opencode run`
на временной папке. Pass: у каждого агента коммиты take, note, done с трейлером `Actor:`.
Прогон платный, запускает агент в конце этапа. Добавить тест на гонку: 5 процессов по 20
`comment`, в файле 100 комментариев и 100 коммитов. TUI проверять через `teatest` и `EDITOR`-заглушку.

M8. Раздел 2. Нет общего правила на непредусмотренное. Есть только «ошибка одной строкой» в CLI.
Нет лога, кода выхода, защиты TUI от паники (терминал остаётся сломанным).
Предложение: одна строка наружу, код выхода не 0, контекст в `.tracker/log` (в `.gitignore`).
TUI ловит панику и восстанавливает терминал.

## Should-fix

S1. spec.md:96, 228. `updated` меняется каждой записью, строки frontmatter соседние.
`git merge-file` даёт ложный конфликт: человек правит `due`, агент `claim`.
Предложение: frontmatter сливать по полям, тело через `merge-file`. Либо убрать `updated`:
дату даёт git. Писать через `yaml.v3` Node, порядок полей не менять.

S2. spec.md:107. Повтор после изменения файла должен идти с шага external edit. Иначе правка
Obsidian уходит в коммит агента. Окно между сверкой и rename назвать принятым риском.

S3. spec.md:139, 228. `J K` с целым `rank` переписывает много файлов. Это противоречит правилу
«файл и один коммит». Предложение: дробный `rank` посередине между соседями, меняется один файл.

S4. spec.md:90, 217. Лок не назван. Предложение: `syscall.Flock` на `.tracker/lock`, он снимается
при смерти процесса. Таймаут 5 с. TUI не блокирует экран.

S5. spec.md:120. Правило проекта по папке не задано. Worktree и подпапка дадут чужое имя.
Предложение: имя родителя `git rev-parse --git-common-dir`, карта в конфиге, `--project`.

S6. Нет `init` и ответа на первый запуск: хук `ctx` при пустом `~/tasks`.
Предложение: создание папки, git, конфига и `.gitignore` при первой записи. `ctx` без папки
печатает одну строку.
Задача - только `T-*.md`: `RULES.md` иначе станет «сломанным файлом».
`.gitignore`: `.obsidian/workspace*`, `.trash/`, `*.swp`, `.tracker/{tmp,lock,log}`.

S7. spec.md:197, 260. Колонку переименовали в конфиге руками, у задач старый `status`.
Сломанный `config.toml`. Предложение: задачи с неизвестным статусом в отдельной колонке `?`.
Ошибка конфига - путь и строка, как у задачи.

## Лестница решений

| Что | Ответ |
|---|---|
| лок | stdlib `syscall.Flock` |
| атомарная запись | stdlib `os.CreateTemp` + `os.Rename` |
| слияние | `git merge-file`, для frontmatter своё на 30 строк |
| frontmatter | `gopkg.in/yaml.v3` Node, сохраняет порядок и чужие поля |
| наблюдение | `fsnotify` |
| `$EDITOR` | `tea.ExecProcess` |
| история | `git log --grep` |
| id, rank | своё: счётчик и середина, готового проще нет |
| тесты TUI | `charmbracelet/x/exp/teatest` |
| трекер целиком | kanban-md близок (Go, claim, context). Своё по Р1, его парсер стоит прочитать |

Обратная сторона: коммит на правку стоит 3-4 процесса git на запись, цифры нет.
`updated` и конфиг тем можно удалить без потери результата.
