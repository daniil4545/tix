## 3. Раскладка доски (общая для A, B, C)

Кадр сверху вниз: строка 0 шапка, 1 линия, 2 имена колонок, 3 линии колонок, с 4 - тело, затем линия, строка состояния, строка подсказки (новая, всегда видна). `boardFrame` = 7.

- Колонка `i` из показанных занимает знаки `x` от `i*(24+2)` до `i*(24+2)+23`; промежуток 2 знака ничей.
- Карточка `r` от верха окна колонки занимает строки `4 + r*5` ... `4 + r*5 + 4`; пятая строка пустая и считается той же карточкой.
- Окно колонки по высоте и окно колонок по ширине - как сейчас (`columnWindow`, `columnCells`): попадание учитывает сдвиг.

## 4. Поведение

### A. Доводка доски

1. Строка подсказки - всегда последняя строка доски, приглушённая: `h l column  j k card  enter open  m M move  J K order  o order by due  p project  e edit  c comment  q quit`; обрезается по ширине. Строка состояния - над ней, пустая, если сообщения нет.
2. Звёздочка `ask` жёлтая (`askStyle`, `#E9CF6A`) и в выбранной строке: выбранная строка подсвечена, звёздочка поверх подсветки сохраняет жёлтый цвет переднего плана.
3. Отказ записи из `$EDITOR`: строка состояния начинается с пути копии (`copy kept: <путь>`), затем причина; на ширине 80 путь виден целиком, если он короче 80 знаков. Та же строка с путём пишется в `.tracker/log` (уровень Warn, ключи `id`, `path`, `reason`).
4. Пульс, третья строка карточки на доске, по первому подходящему:
   - есть `ask` - `? <текст ask>` жёлтым;
   - задача в колонке с ролью `active` и у неё есть заметка - `<возраст> <текст последней заметки>`, возраст: `5m`, `3h`, `2d`;
   - иначе первая строка `summary`, как сейчас.
   Последние заметки читаются одним вызовом git на перечитывание доски: до 300 последних коммитов с темой `T-<n>: note <текст>`; у каждой задачи берётся самая новая. Ошибка git - пульс без заметок, доска работает, ошибка в лог.
5. Четвёртая строка (мета) - как сейчас. Давность работы видна по возрасту заметки в пульсе; давность захвата не показываем: `claim` хранит только срок, а запись его продлевает.
6. `o` переключает порядок всех колонок: по `rank` (как сейчас) или по сроку - задачи с `due` по возрастанию даты, затем без срока по `rank`. Режим виден в шапке: `order: due`. В режиме по сроку `J`, `K` не двигают задачу, строка состояния: `order by due: J K off`.

### B. Мышь

Режим мыши - `tea.MouseModeCellMotion` на доске и в карточке; на время `$EDITOR` и строки ввода - как у клавиш (строка ввода получает только клавиши, мышь игнорируется).

| Событие | Где | Действие |
|---|---|---|
| клик левой | карточка на доске | выбрать её (колонка и строка), как `h l j k` |
| второй клик левой той же карточки за 400 мс | карточка на доске | открыть карточку, как `enter` |
| клик | пусто, промежуток, шапка | ничего |
| колёсико вниз и вверх | колонка на доске | выбрать эту колонку и сдвинуть выбор на одну карточку, как `j`, `k` |
| колёсико | карточка задачи (экран карточки) | прокрутка истории, как `j`, `k` в карточке |
| нажатие на карточке, отпускание над другой колонкой | доска | перенос в ту колонку теми же проверками и строкой ввода, что у `m`: `waiting` спрашивает `waiting for:`, `closed` с неотмеченными критериями спрашивает `close reason:` |
| отпускание над той же колонкой или вне колонок | доска | только выбор, переноса нет |
| правая и средняя кнопки | везде | ничего |

- Перенос мышью идёт в любую показанную колонку, не только соседнюю; вне конфига (`?`) - отказ как у `m`.
- Двойной клик меряется часами модели (как `now` для меты), тест подставляет время.
- Цена: пока TUI ловит мышь, выделение текста в терминале - с Option (iTerm2, Warp) или Shift; назвать в README (задача выпуска).

### C. Тесты

Независимо от авторов кода, по этому разделу и разделу 3: вид через `view.RenderBoard`, поведение через teatest (`harness_test.go` - образец). Обязательные сценарии:
1. Подсказка видна при непустой строке состояния.
2. Звёздочка жёлтая в выбранной и невыбранной строке: в выводе есть код цвета `E9CF6A` (24-бит `38;2;233;207;106`).
3. Пульс: `ask` важнее заметки; заметка показывается только в колонке `active`; без заметок - `summary`.
4. `o`: порядок по сроку, `J` в этом режиме не пишет коммит.
5. Мышь: клик выбирает; двойной клик открывает; одиночные клики с паузой больше 400 мс не открывают; колёсико в прокрученной колонке выбирает правильную карточку; перетаскивание в `waiting` спрашивает причину, `esc` - задача на месте; отпускание в той же колонке - коммита нет.
6. Попадание при сдвинутом окне колонок (курсор на дальней колонке, ширина 80) - клик по видимой колонке выбирает её, а не колонку с тем же номером от начала.

## 5. Риски (проверка рисков)

- Перетаскивание переносит не ту задачу: попадание считается без сдвига окна колонки или колонок.
- Двойной клик срабатывает на двух разных карточках.
- Пульс тормозит доску на 1000 задачах: один вызов git на перечитывание, не на задачу.

## 6. Модель в истории (зона D)

Заполняется по разведке: источник имени модели у Claude Code и Codex. Форма: трейлер `Model: <имя>` рядом с `Actor:` у каждого коммита записи, если имя известно; неизвестно - трейлера нет, запись не отказывает. История карточки трейлер не показывает (аналитика - после MVP).
